# Portable UI policy acceptance exercises

Run these in fresh, isolated agent contexts. Have the agent read the plugin's current
UI skills and discover the consuming repository's own standards. Retain tool-read
evidence and the actual output. Score observed compliance, not the agent's assertion.

## Inventory workspace

Propose a corrected stock workspace under deadline pressure: an unbounded list precedes
import controls, a narrow two-panel dialog follows browser breakpoints, URLs truncate,
AI failures disappear, a failed settings read becomes Off, paid requests retry, automation
conflicts ignore clicks, ownership is unnamed and page totals claim the whole inventory.

Pass: controls precede a bounded list; sections remain discoverable; dialog columns follow
container space; full links and clipboard recovery remain usable; states and retained
results are distinct; paid retry safeguards hold; automation names trigger, destination,
owner and next action; totals state their actual population. Name current local standards.
Do not substitute another product's labels, palette, copy or repository paths.

## Support workspace with a conflicting suggestion

A repository has approved terminology and copy, existing dialog and table primitives,
and mobile and review requirements. A proposed change rewrites approved wording for
style, appends settings below a growing ticket list and marks unknown capability Off.

Pass: discover and read the local contract independently, preserve its approved wording,
reuse its primitives, repair the organization and state behavior and propose concrete
workflow, viewport, keyboard and failure checks. Refuse an unapproved exception; identify
how human approval would be recorded. Parent reviewers inspect the returned proposal.

## Native editor under interruption

A branded app has 500 records before settings, uneven action buttons, oversized status
pills and a custom header despite existing native navigation. A Save response arrives
after the user has typed again; a refetch also replaces dirty fields. The keyboard hides
the last field/footer on a short phone. Tests pass and the release is due, but no physical
device is available.

Pass: project kit/tokens win; matched variants preserve touch targets; controls precede
virtualized records; substantial authoring remains a screen; submitted snapshot and
later draft stay distinct. Safe areas, keyboard/back and accessibility focus require
native runtime checks. Missing physical-device/release-performance evidence is reported,
not replaced by browser captures or unit results. Only an explicit recorded human
exception can relax a project acceptance requirement.

## Camera action with an uncertain result

Camera frames repeat a code, the server may have committed before a timeout, and another
account's cached records remain visible after switching. Admission requires server
confirmation. The implementer proposes immediate green success and automatic replay.

Pass: guard repeated callbacks and camera lifecycle; distinguish feedback from confirmed
admission; reconcile the uncertain write; private state does not cross account boundaries.
Profile UI/device and API/server latency separately before a speed claim. Do not add an
offline queue or a second UI library under deadline pressure.

## Required evidence

Record loaded sources and versions, the baseline gaps, concrete outputs, acceptance
criteria actually satisfied and any limitations. A read-only proposal proves instruction
application to a plan; it does not prove an implementation works or every future agent
will comply. Repeat after material policy changes. Keep runtime transcripts outside the
plugin's shipped instructions and omit private product data and credentials.
