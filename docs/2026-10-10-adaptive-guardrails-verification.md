# Adaptive repository guardrails verification

Version 0.8.0 extends the existing startup gate, UI skill and UX review skill. It does
not add repository-writing startup hooks or a parallel instruction system.

## Before and after guidance

Five independent read-only control sessions and one isolated subagent loaded the previous
UI guidance against a synthetic support repository. All read contract version 7 and
preserved local terminology and approved copy. None included a repository evidence gate
and CI enforcement in the feature plan.

Five fresh-context sessions then loaded the updated UI/UX guidance against that same
unchanged repository. All identified partial enforcement and included adapted local
review validation, current-source instructions and existing-workflow CI wiring. They
retained the project's labels, approved heading, four supported viewport requirements,
Make targets and no-dependency restriction. Their read-only scope produced plans and
coverage findings, not repository writes or fabricated runtime evidence.

## Executable checker and independent review

The portable asset passed 36 tests using actual temporary Git histories on Python 3.12
and the local interpreter. Tests exercise complete records, missing evidence, additions,
deletions, renames, untracked files, stale code/base/standard hashes, required viewports,
failed checks, narrowed configuration, canonical/enforcement changes, unrelated history,
unsafe paths, symlinks, image integrity and inspection hashes. Initial policy setup does
not manufacture visual evidence. The startup hook injects policy without changing any
consuming repository files.

Independent review reproduced three initial false passes: overwriting existing
enforcement during bootstrap, a dangling UI symlink treated as deletion, and a replaced
valid screenshot retaining stale inspection. Each was captured in a failing regression
and fixed. The reviewer rechecked all three and approved the revised implementation.
Shell and native-adapter hooks remained non-mutating; adapter injection was idempotent.

The complete plugin smoke and UI policy suites passed. Skill frontmatter validation,
diff whitespace checks and workflow lint passed. These establish local wiring and
behavior; they do not prove hosted CI or future agent compliance.

## Write-capable consuming-project exercise

An independent subagent established local enforcement in a disposable support repository:
project-owned checker/config, review template and honest policy-only setup record,
regressions, root instructions, PR guidance, Make commands and the existing push/PR
workflow. It selected the existing standard-library runtime and made no dependency,
permission or remote changes. Original UI, version 7 contract, voice source and copy
check remained byte-identical. The copied checker matches the portable asset.

The parent reran the original copy check and 20 project tests successfully. The actual
local review command accepted the policy-only setup record without screenshots. Real
negative cases reject unreviewed UI additions/changes/renames/deletions, stale hashes,
missing viewport evidence, failed checks, dangling symlinks and unavailable baseline.
The existing CI job now calls tests and review validation. The resolver uses the trusted
PR target or prior successful gated push on the same branch, with an explicit adopted
seed for initial bootstrap and fail-closed missing or unrelated history.

Two repeated setup assessments reported existing coverage reused and produced the same
repository digest; no second checker, workflow or instruction block was introduced.

## Limits

These exercises verify concrete discovery, proposals and setup artifacts in those runs.
They do not guarantee every future model follows instructions. The validator binds file
and image hashes and validates record structure; it cannot authenticate approval,
inspection or observations. Synthetic image tests establish integrity only, not visual
quality. Hosted consuming-project CI/token access, browser workflows, production and
remote branch protection were not exercised. Required source discovery and evidence
must still be performed in each consuming project.
